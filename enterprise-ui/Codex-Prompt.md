# Codex 高保真还原执行提示词

你是一名资深企业级前端工程师与 UI 还原工程师。请以本目录 reference.png 和 Design-System.md 为唯一视觉基准，对现有企业知识库的对话问答页面进行高保真改版。目标是1920×1080桌面端真实可交互页面，而不是宣传图。保留现有技术栈、路由、API、权限、流式问答、历史会话、文档引用、服务状态和主题切换，不重写后端。

## 阶段一：勘察
先读取 package.json、路由、布局、聊天页面、请求层、状态管理、主题变量和现有组件。输出文件清单、业务能力映射、复用计划、设计差异与风险。确认项目实际技术栈，不假定 Vue 或 React。检查 assets 中每张图片尺寸、透明通道和用途，禁止把带背景的 hero 当透明图。未实现的通知、附件、用户菜单只列为待确认，不新增假接口。

## 阶段二：实现
1. 建立全局 CSS tokens，局部作用域避免污染其他页面。深蓝侧栏宽280px，白色 Header 高92px；按 Design-System.md 坐标建立布局，使用 Grid/Flex，禁止绝对定位整页。
2. Sidebar 保留对话问答、文档管理、检索调优（若原路由名称为检索调试则保留）、服务状态。菜单图标使用独立 PNG，选中项蓝色背景，白字，hover 不跳动。Logo 使用现有品牌或提供的资源。
3. 欢迎区左侧标题“智能问答 · 企业知识随时可用”，后半段科技蓝；副标题“基于企业知识库的智能问答，快速获取准确、可信的专业信息”。右侧使用主视觉，保持比例，背景用 CSS 实现。不得遮挡文字。
4. 输入框位于欢迎区下方，宽约1304px、高102px，圆角51px，白底、蓝色细边、柔和阴影。占位“输入问题，获取企业知识库的答案...”。发送按钮根据空值、请求中、流式状态切换。附件仅在真实支持时显示。保留 IME 处理、键盘发送和防重复提交。
5. 快捷问题三项横排：“近期合同的审批流程是怎样的？”、“新员工入职需要办理哪些手续？”、“如何配置智慧化部署计划？”；可配置，点击填入输入框，不伪造答案。
6. 底部三张功能卡：“快速问答”“知识沉淀”“持续优化”，分别展示原稿蓝、紫、绿图标块。标题和描述使用真实文本。仅在路由存在时可点击。
7. 进入真实对话后隐藏欢迎区及功能卡，保留导航和顶部，消息区域滚动，输入区固定在内容区底部。引用、复制、重试、停止、历史会话均复用现有逻辑。
8. 新对话、历史会话、服务就绪和深浅主题是原页面已有功能，必须保留；设计稿未画出的位置允许在 Header 或侧栏中以低强调方式补齐，并记录差异。

## 阶段三：视觉验收
启动现有项目，使用浏览器或项目已有 Playwright 测试。固定 viewport 1920×1080、DPR 1、100% 缩放、相同字体，等待图片与字体加载。输出 actual.png、overlay.png（50%叠加）、diff.png。逐项核对侧栏、Header、标题、插画、输入框、快捷问题、功能卡。核心几何目标≤4px；先修布局再修字号、色彩、阴影。不得用整页截图、缩放整页或硬编码虚假业务数据降低差异。重复截图对比直到达到约定阈值或明确记录剩余差异。再测试1440×900、1366×768及1024×768。

## 阶段四：交付
提交实际代码、修改文件清单、组件说明、资源映射、截图对比、测试结果、未解决问题。运行项目已有 lint/typecheck/test/build 命令并记录真实结果。没有可用浏览器或后端时明确标注未验证，不宣称100%还原。禁止引入无关依赖、删除原有功能或更改 API 契约。优先实现真实产品可用性，再追求像素级一致。
