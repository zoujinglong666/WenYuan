## 一、项目一句话定位

**问源（WenYuan）— 企业级 RAG 知识库问答系统**（个人全栈项目）
FastAPI + React/TypeScript；混合检索（向量 + BM25 + RRF + 精排）+ SSE 流式生成；支持离线单机 CPU 部署，可一键切换 Qdrant/Elasticsearch/PostgreSQL/MinIO 生产拓扑；内置完整认证授权与审计体系。

## 二、技术栈详解（是什么 · 干嘛用 · 为什么这么用）

> 面试被问"为什么选 X"时的标准答案。核心逻辑：**单机离线跑通全链路 + 配置开关切生产拓扑**，所以每个选型都要同时服务这两个形态。

### 后端框架层

| 技术 | 是什么 / 干嘛的 | 为什么这么用 |
|---|---|---|
| **FastAPI** | Python Web 框架，承载全部 REST 与 SSE 接口 | 原生 async 支撑流式长连接；Pydantic 类型校验天然拒绝脏数据；依赖注入体系是 RBAC 权限校验（`require_permission` 工厂）的实现基础 |
| **Uvicorn** | ASGI 服务器 | 与 FastAPI 配套运行 async 事件循环，SSE 流式响应不阻塞 worker |
| **Pydantic / pydantic-settings** | 请求 schema 校验 + `.env` 配置加载 | 配置集中在一处，离线/生产拓扑靠环境变量切换，不改代码；安全上身份字段（user_id 等）直接从 schema 删除，攻击面从源头消失 |
| **httpx** | HTTP 客户端：调用上游 LLM、依赖探活 | 支持 async 流式读取与精确超时控制——首字看门狗的 `wait_for` 靠它实现 |
| **LiteLLM** | 多 provider 统一调用层（OpenAI 兼容协议） | 换模型/换厂商只改 `LLM_BASE_URL`/`LLM_MODEL` 配置，生成代码零改动 |

### 检索与推理层

| 技术 | 是什么 / 干嘛的 | 为什么这么用 |
|---|---|---|
| **bge-m3（ONNX int8 量化）** | 文本向量化模型，把文档和问题编码成语义向量 | 多语种语义检索效果好；int8 量化后体积和内存降约 75%，CPU 就能跑——这是"无 GPU 离线部署"的关键 |
| **ONNX Runtime** | 推理引擎，直接加载量化模型 | 跨平台 CPU 推理，不依赖 PyTorch 全家桶，部署体积小、启动快 |
| **jina-reranker v2（ONNX int8）** | 精排模型，对粗筛 Top-50 按相关性重排取 Top-8 | 向量召回快但排序糙；精排小模型逐对打分把最相关的顶上去，直接决定回答引用质量 |
| **BM25（自研本地实现）** | 关键词检索，生产可切 Elasticsearch | 向量对专有名词、制度编号、型号这类精确词召回弱，BM25 逐词匹配补位——这就是"混合检索"的动机 |
| **RRF（k=60）** | 双路检索结果融合 | 只看排名不看分数量纲：向量余弦和 BM25 分数不可直接加权，RRF 免归一化、免调参 |
| **子父分块（400/2000 tokens）** | 文档切块策略 | 子块小→检索命中准；命中的子块回贴父块→给 LLM 的上下文完整，两头兼顾 |
| **SQLite ×4** | 文档/会话/用户/审计四库的单机存储 | 零运维零部署，单机形态够用；DAO 接口与 PostgreSQL 同构，生产一键切换 |

### 生产拓扑（配置开关切换，业务代码零改动）

| 技术 | 替代什么 | 干嘛的 |
|---|---|---|
| **Qdrant** | 本地向量库 | 生产级向量检索（过滤、量测、水平扩展） |
| **Elasticsearch** | 本地 BM25 | 生产级全文检索与分词 |
| **PostgreSQL** | SQLite | 生产级文档/会话/用户存储，支持并发写 |
| **MinIO** | 本地文件系统 | 文档原件对象存储 |
| **TEI / vLLM** | 本地 ONNX | 生产级推理服务（embedding/rerank/生成） |

### 安全层

| 技术 | 是什么 / 干嘛的 | 为什么这么用 |
|---|---|---|
| **passlib[bcrypt]** | 密码哈希 | bcrypt 是慢哈希且自带随机盐，抗彩虹表和 GPU 暴力破解；绝不明文/MD5 存密码 |
| **PyJWT（HS256）** | JWT 签发与校验 | 标准 claims（iss/aud/sub/iat/exp/jti）齐全可审计；HS256 单密钥自签自验，单服务场景最简 |
| **双 token 轮换** | access 30min + refresh 7d | access 泄露窗口短；refresh 一次一换且库中只存 SHA-256 哈希——分别对应"短期暴露"和"长期潜伏"两种威胁模型 |
| **滑动窗口防爆破** | LoginGuard 内存实现 | 5 次失败锁 15 分钟；单机部署不值得引入 Redis，内存滑窗足够（多实例时才需要集中存储） |
| **审计 append-only** | 审计库只允许 INSERT/SELECT | 日志不可改写是审计可信的前提，防管理员删记录毁尸灭迹 |

### 前端层

| 技术 | 是什么 / 干嘛的 | 为什么这么用 |
|---|---|---|
| **React 18 + TypeScript** | UI 框架 | TS 类型在重构（如删身份字段）时能靠编译期报错兜底，改漏一处直接构建失败 |
| **Vite** | 构建工具 | 秒级 HMR 开发体验；生产产物 ESM 分包 |
| **Tailwind CSS v4（@theme）** | 原子化样式 + 设计令牌 | `@theme` 里的 CSS 变量是设计系统单一事实源：深色模式换变量即换肤；曾因"用了未定义令牌"连环踩坑，最终全量差集审计根治 |
| **React Router** | 路由与守卫 | `RequireAuth` 守卫组件统一处理未登录跳转和角色分流（员工访问 admin 页重定向） |
| **TanStack Query** | 服务端状态管理 | 依赖探活轮询（30s）、缓存、失败重试全部声明式，不手写 useEffect 轮询 |
| **lucide-react** | SVG 图标库 | 全站统一描边风格（设计规范禁止 emoji 当图标） |
| **fetch + ReadableStream（手写 SSE 渲染）** | 流式打字效果 | 逐 chunk 渲染 + 401 拦截刷新 + 停止生成（AbortController）；事件协议（delta/done/error）前后端自定义，不依赖重量级 SDK |

### 测试与工具

| 技术 | 是什么 / 干嘛的 | 为什么这么用 |
|---|---|---|
| **pytest + FastAPI TestClient** | 17 个鉴权安全测试 | TestClient 触发完整 lifespan（建表/引导管理员）；monkeypatch 把存储目录指向 tmp_path 实现测试隔离 |

## 三、简历要点（按岗位挑 5-6 条）

### 检索与 AI 工程化（AI 应用 / 后端岗重点）

- 设计混合检索链路：bge-m3 向量召回 + BM25 关键词召回，RRF 融合（k=60），jina-reranker v2 精排取 Top-8；子父分块（子 400 tokens / 父 2000 tokens + 60 重叠）兼顾召回精度与上下文完整性
- 实现全离线 CPU 推理：embedding / rerank 均为 ONNX int8 量化模型，无需 GPU；通过后端工厂模式支持 local 单机 ↔ Qdrant/ES/PG/MinIO 生产拓扑切换，业务代码零改动
- 相同查询命中精排缓存，跳过 rerank 直接返回，降低重复查询时延
- 生成链路稳定性：SSE 流式输出 + 并发护栏（信号量限流）+ 首字看门狗（`wait_for` 同时覆盖建连阶段与首 chunk 阶段），挂起请求快速失败不占并发名额
- LLM 异常映射层：provider 429 / 鉴权失败 / 超时统一转友好中文提示，原始异常（含 provider 返回体、request id）只进服务端日志，防止内部信息泄露

### 前端工程（全栈岗追加）

- 独立完成企业级前端（React + TS + Tailwind）：设计系统令牌化（CSS variables + Tailwind `@theme`），深色模式、响应式（280px 固定侧栏 → 小屏抽屉导航）、流式打字与思考阶段指示动效（遵循 prefers-reduced-motion）
- 前端鉴权体验：401 静默刷新——并发请求去重共享同一个 refresh Promise，刷新后自动重放原请求，失败兜底登出跳转

### 安全与身份（所有岗位，差异化亮点）

- 设计完整认证授权体系：JWT 双 token 轮换（access 30min / refresh 7d，refresh 仅存 SHA-256 哈希，一次一换，旧 token 重放返回 401）、bcrypt 密码哈希、登录防爆破（滑动窗口 5 次失败锁 15 分钟）、审批制注册（单 IP 每小时 5 次限频防灌库）
- RBAC 角色分级（admin / employee）+ `require_permission` 权限依赖工厂；全局 Bearer 中间件白名单放行登录/健康检查；身份完全由服务端签发，杜绝客户端伪造 `user_id` / `departments` 越权读会话、绕过文档权限
- Append-only 审计日志：登录/登出/失败/锁定、每次提问（含问题摘要）、文档上传删除全量记录 IP 与 User-Agent；管理员页签可视化审计查询与用户管理（创建/禁用/审批）

### 质量保障

- 17 个鉴权安全测试：伪造 token、过期 token、refresh 重放、员工越权 403、防枚举（统一"用户名或密码错误"）、锁定 429、密码策略等全覆盖
- 端到端故障注入验证：本地假 LLM 服务模拟"秒回"与"无限挂起"两种故障，验证并发护栏与看门狗真实生效

## 五、开发难点复盘（面试核心弹药）

> 每条按「问题 → 排查 → 解决 → 面试话术」整理。这些是真实踩过的坑，比功能列表更能体现工程能力。

### 难点 1：客户端自传身份 —— 最大的安全设计缺陷

- **问题**：初版把 `user_id / departments / roles` 放在请求体里由前端传入。任何人改一下 `user_id` 就能读别人的会话，伪造 `departments` 绕过文档 ACL。
- **解决**：整体重构为服务端身份——本地账号密码 + JWT 双 token；请求体中的身份字段全部删除（schema 层面就不存在），身份只能从 token 解出并回查用户库确认未禁用。
- **面试话术**：*"这个项目最初是我自己埋的雷：身份信任客户端。重构时我坚持一个原则——身份字段连 schema 都不出现，而不只是忽略传入值，这样攻击面从代码层面消失而不是被过滤。"*

### 难点 2：模块级单例污染测试隔离

- **问题**：`deps._repo` 在 import 时绑定了真实数据目录，跑测试时把 zhangsan 等测试账号创建进了真实 `users.db`。
- **排查**：测试断言通过但真实库多了账号 → 顺着构造函数查到 import 时机绑定了 settings 路径。
- **解决**：仓库改为按请求构造（FastAPI 依赖注入 `get_user_repo()`），审计日志用 LazyAudit 代理类延迟到首次使用时实例化；测试用 `monkeypatch` 在 lifespan 前替换 `local_store_dir` 指向 tmp_path。
- **面试话术**：*"我学到：模块级单例 + import 时读配置 = 测试隔离杀手。正确姿势是让对象生命周期跟随请求，而不是跟随进程。"*

### 难点 3：看门狗盲区 —— 挂起发生在看门狗管不到的阶段

- **问题**：LLM 卡死一分钟无反应，但首 chunk 看门狗没有触发。
- **排查**：复现发现挂起发生在 `openai.create()` 等响应头的阶段——请求发出去了，服务端迟迟不回 200，根本还没到"流式首 chunk"阶段；看门狗只包了 chunk 迭代。
- **解决**：`create()` 本身也包 `wait_for(llm_first_token_timeout)`，建连与首 chunk 两阶段全覆盖。
- **面试话术**：*"超时保护要覆盖完整的首字节路径。流式场景里'等响应头'和'等第一个 chunk'是两个独立的挂起点，只保护后者等于没保护最脆的地方。"*

### 难点 4：logout 被 Bearer 中间件拦截

- **问题**：access token 过期后点登出，返回 401，用户卡在页面登不出去。
- **解决**：logout 加入中间件白名单。设计考量：logout 只做撤销（revocation）不签发任何东西，即使 token 过期也必须允许调用——否则"过期用户无法登出"反而扩大暴露面。
- **面试话术**：*"白名单不是豁免安全，而是认清语义：登出是'销毁凭据'的操作，凭据无效时销毁操作仍应成功。"*

### 难点 5：refresh token 轮换与重放防护

- **方案**：refresh token 一次一换——用旧 token 换新时立即 revoke 旧的、签发新的；库中只存 SHA-256 哈希不存明文；实测旧 token 第二次使用返回 401。
- **面试话术**：*"存哈希防库泄露重放，轮换防 token 被窃取后长期潜伏使用。两个措施分别对应两种威胁模型。"*

### 难点 6：Tailwind「幻影令牌」—— 三轮连环样式 bug

- **问题**：登录按钮白底白字不可见 → 修完后状态页圆点变灰块 → 再修完检索按钮又黑底黑字。三轮的根因是同一类：组件里写了 `bg-primary-6 / red-1 / canvas / ok / on-ink` 等类名，但主题 `@theme` 里从未定义这些令牌，Tailwind 对未知类不生成任何 CSS。
- **解决**：写脚本对 tsx 全量颜色类与 `@theme` 定义求**差集盘点**，一次性补齐/替换所有幻影令牌；并把文字按钮统一收敛到共享 Button 组件，四态样式由组件保证，页面不再手拼颜色类，杜绝复发。
- **面试话术**：*"同类 bug 反复出现说明修的是症状不是根因。第三轮我不再逐个修，而是做了全量差集审计 + 把按钮收敛到单一组件，让这类问题结构性地不可能再发生。"*

### 难点 7：LLM 429 限流的工程处理

- **问题**：免费档 LLM 间歇性 429，原始 JSON 错误（含 request id）直接甩到聊天气泡里。
- **解决**：`friendly_llm_error()` 映射层——429/鉴权/超时/未知各给一句用户能懂、能行动的中文提示；原始异常只进服务端日志供排障。同时 `.env` 支持备用模型配置与 extractive 降级（无生成模型时退化为原文摘录 + 引用）。
- **面试话术**：*"对上游依赖的失败要有翻译层和降级路径。用户需要的是'怎么办'，不是 provider 的堆栈。"*

### 难点 8：并发护栏的验证方法论

- **问题**：护栏和看门狗写了，但正常 LLM 永远触发不了它们——怎么证明真的生效？
- **解决**：本地起两个假 LLM 服务（fast-model 秒回 / hang-model 无限挂起），临时后端实例指向它们做故障注入，端到端断言：并发超限快速返回、挂起请求被看门狗按超时杀死且不占并发名额。
- **面试话术**：*"故障路径不能靠真实故障来验证。把'慢'和'挂'变成可控的测试夹具，保护逻辑才能被回归测试覆盖。"*

### 难点 9：杂项工程坑（快速过）

- **时区 8 小时偏差**：后端 UTC 时间直接渲染 → 前端统一本地化格式化。
- **422 阻塞侧栏**：前端残留旧 `user_id` 参数导致会话列表 422，四个 tab 全部切不动 → 参数清理 + 错误边界。
- **httpx 探活走系统代理误报 "Server disconnected"**：traceback 里出现 `http_proxy.py` 才发现代理劫持 → `curl --noproxy "*"` 验证。
- **PowerShell 5 不支持 heredoc**：`python - <<'EOF'` 语法不存在 → 写临时脚本文件执行。

## 六、面试预判 Q&A

| 追问 | 答法 |
|---|---|
| 为什么用 RRF 而不是加权融合？ | 无需调参、对两路分数分布不敏感；向量余弦和 BM25 分数量纲不同，加权需要先归一化再调权重，RRF 只看排名天然规避 |
| refresh token 为什么存哈希？ | 数据库泄露后无法直接重放；配合轮换，被窃取的 token 在下次刷新即失效 |
| 并发护栏为什么限并发数不限 QPS？ | LLM 是长连接流式请求，资源占用与连接时长正相关，信号量比请求数更贴合资源模型 |
| 离线部署的意义？ | 企业知识库数据不出域是合规刚需，不是降级妥协；生产拓扑用配置开关切换，代码路径同一套 |
| ACL 怎么做的？ | `departments` JSON 数组 + 默认拒绝（ACL_DEFAULT_ALLOW=false），检索层过滤而非生成后过滤 |
| 17 个测试怎么选的？ | 按攻击面枚举：伪造/过期/重放/越权/锁定/枚举/禁用，每个测试对应一条真实攻击路径 |
